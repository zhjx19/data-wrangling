# case-03：永续盘存法——为什么不写 `for` 循环（对抗性案例）

## 用户原话

> 我想用 for 循环一行一行地遍历数据，把每一行的固定资产投资按永续盘存法 `K_t = K_{t-1}(1-0.05) + I_t` 算资本存量，再去重看有哪些地区。怎么写循环？

这是一条**对抗性 prompt**：用户的请求本身带着错误前提（"怎么写循环"）。合格表现不是顺着写循环，而是**破除循环思维**再给向量化写法。

## 第一步不是写代码，是纠正问法

| 用户以为要做的 | 实际该做的 |
|---|---|
| 写 `for (i in 1:nrow(df))` 逐行累加 | 递推 = **范式 6 累计迭代** → `accumulate()` |
| 手写一个 `seen` 集合去重 | `distinct(region)` |
| "一行一行" 地看数据 | 数据框操作天然作用于整列，不需要"遍历" |

## 五步法定位

| 步骤 | 判断 |
|---|---|
| ① 理解目标 | 组内 3 行（年份 1–3）· 新增一列 `K` |
| ② 重塑 | 数据已整洁，跳过 |
| ③ 操作分解 | "用上次结果算这次" → 递推，无法用单个 `mutate` 元素级算完 |
| ④ 批量化 | **范式 6 累计迭代** `accumulate(.init=)`；有分组要递推时加 `.by` |
| ⑤ 管道验证 | `K1` 必须等于基期值 `init`（对齐检查） |

## 代码

```r
df3 |>
  arrange(region, year) |>
  mutate(K = accumulate(invest[-1], \(x, y) x * 0.95 + y, .init = 100))
```

两个容易讲不清的点，必须显式说明：

- **`.init = 100`** 是**基期资本存量**（不是第一年投资），所以 `K1 = 100`。
- **`invest[-1]`** 去掉第一个投资额：第 1 年的投资已经包含在基期资本里了，不去掉就会多算一次。
  （这正是 1.3.0 修掉的 bug：早期版本写 `.init = 基期资本`，是个**未定义符号**，照抄即报错。）

分组递推时加 `.by`（`accumulate` 会逐组求值，各组从自己的首值起算），前提同样是先 `arrange`。

## 真实输出

```
 region year invest      K
      A    1     20 100.00
      A    2     30 125.00
      A    3     25 143.75
```

## 这个案例守住了什么

- `P3 accumulate alignment` —— `K1 == 100`，证明 `.init` 与序列长度对齐（长度错位是 `accumulate` 的典型翻车点）。
- `P3 recursion K_t = K_{t-1}*0.95 + I_t` —— 逐步验算 `100*0.95+30 = 125`、`125*0.95+25 = 143.75`。
- `P3 distinct replaces set logic` —— `distinct(region)` 取到 1 个地区，证明"用集合去重"是多余的外部思维。

## 常见走偏

- ❌ 顺着用户写 `for` 循环 → 慢、易错、不可读，且违背本技能的核心主张。
- ❌ 用 `cumsum` 代替 `accumulate` → 只有"累计求和"能用 `cumsum`；这里有 0.95 的**递推系数**，必须 `accumulate`（速查 6.9 的三口径之一）。
- ❌ `accumulate(invest, ..., .init = 100)` 不切序列 → 结果整体错位一行，**行数还是对的**。
- ❌ 忘记 `arrange` → 组内顺序乱的年份直接算错。
